Q3: Overwrite — snapshot BEFORE delete? Rollback on error?
-----------------------------------------------------------
Answer: ✅ YES — snapshot created before clearAll. Rollback exists.
Evidence — backup_service.dart lines 131-143:
  if (overwrite) {
    await _snapshotManager.createSnapshot(          // ← STEP 1: snapshot FIRST
      collections: _storageService.getAllCollections(),
      items: _storageService.getAllItems(),
      widgetConfigs: _storageService.getAllWidgetConfigs(),
    );
    try {
      await _storageService.restoreFromBackup(      // ← STEP 2: clearAll + write new data
        collections: collections,
        items: items,
        widgetConfigs: widgetConfigs,
      );
    } catch (e) {
      await _snapshotManager.restoreLatestSnapshot(_storageService);  // ← STEP 3: rollback
      return ImportResult(success: false, message: 'Import failed. Previous data restored from safety snapshot.');
    }
  }

Test case — mid-process failure:
  Scenario: clearAll() succeeds, but writing 2nd collection fails.
  - Snapshot was created BEFORE clearAll ✅
  - clearAll() removes all data
  - restoreFromBackup() starts writing collections
  - Exception thrown at 2nd collection.put()
  - catch block calls restoreLatestSnapshot() ✅
  - Data restored to pre-overwrite state ✅
  VERDICT: Correct for exception-based failures.

⚠️ LIMITATION: If app process is killed (SIGKILL) mid-restore,
the snapshot file exists but no code auto-restores it.
User must manually restore from Backup Screen → Safety Snapshots.
This is acceptable for MVP — true crash recovery would require
a separate watchdog service.
