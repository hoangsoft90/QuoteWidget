--- A1. Collection rỗng vẫn là dead-end khi tap ---

BUG:
  Trạng thái "Collection rỗng" (text="") dùng PendingIntent.getBroadcast()
  → handleTap() khi tap. handleTap() không làm gì vì totalItems=0 → dead-end.

FIX: 3-way branching trong updateAppWidget():

  if (collectionId.isEmpty() || isRemoved) {
      // Unconfigured / removed → open app → WidgetSetupScreen (pick collection)
      → PendingIntent.getActivity()
      → Extras: appWidgetId

  } else if (text.isEmpty()) {
      // Collection configured but empty → open app → add items
      → PendingIntent.getActivity()
      → Extras: appWidgetId + collectionId

  } else {
      // Configured widget with content → cycle (internal broadcast)
      → PendingIntent.getBroadcast()
      → Extras: widget_id
  }

Flutter routing:
  - main.dart reads tapped_widget_id + tapped_collection_id từ SharedPreferences
  - WidgetSetupScreen nhận optional collectionId
  - Nếu collectionId có → auto-create WidgetConfig → navigate CollectionDetailScreen
  - Nếu collectionId null → hiện collection picker (first-time setup)

Files sửa:
  - QuoteWidgetProvider.kt: 3-way PendingIntent branching
  - main.dart: đọc tapped_collection_id, pass vào QuoteWidgetApp
  - widget_setup_screen.dart: accept collectionId, auto-save + navigate to detail

--- A2. Warm-start: deep link có thể không hoạt động nếu app đã chạy sẵn ---

BUG:
  main.dart đọc tapped_widget_id lúc Flutter engine khởi động (cold start).
  Nếu app đang chạy background → Activity lên foreground nhưng KHÔNG chạy
  lại main() → deep link bị mất.

FIX: Dual-layer approach

Layer 1 — MainActivity.onNewIntent() (Kotlin):
  override fun onNewIntent(intent: Intent) {
      super.onNewIntent(intent)
      setIntent(intent) // Bắt buộc trên Android
      // Ghi tapped_widget_id + tapped_collection_id vào SharedPreferences
      // để Flutter đọc khi resume
  }

Layer 2 — WidgetsBindingObserver (Flutter):
  class _QuoteWidgetAppState ... with WidgetsBindingObserver {
      @override
      void didChangeAppLifecycleState(AppLifecycleState state) {
          if (state == AppLifecycleState.resumed) {
              _checkPendingWidgetTap(); // Đọc SharedPreferences
          }
      }
  }

Flow warm-start:
  1. User tap widget (app đang background)
  2. Android gọi onNewIntent() → ghi tapped_widget_id vào SharedPreferences
  3. Android đưa Activity lên foreground
  4. Flutter resume → didChangeAppLifecycleState(resumed) fires
  5. _checkPendingWidgetTap() đọc SharedPreferences → tìm thấy tapped_widget_id
  6. Navigate tới WidgetSetupScreen

Tại sao dùng fallback thay vì MethodChannel:
  MethodChannel yêu cầu Flutter engine sẵn sàng khi onNewIntent() fires.
  Với FLAG_ACTIVITY_CLEAR_TOP, Activity có thể resume trước khi engine
  khởi động xong. SharedPreferences + lifecycle observer đơn giản hơn
  và đáng tin cậy hơn.

Files sửa:
  - MainActivity.kt: thêm onNewIntent() override
  - main.dart: thêm WidgetsBindingObserver + _checkPendingWidgetTap()
