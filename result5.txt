Q2: ĐÃ FIX — 2 PENDINGINTENT KHÁC NHAU TÙY TRẠNG THÁI
================================================================================

QuoteWidgetProvider.kt — updateAppWidget() now has branching:

  if (collectionId.isEmpty() || isRemoved) {
      // Unconfigured / removed → open app for configuration
      val configPrefs = getPrefs(context)
      configPrefs.edit().putString("tapped_widget_id", appWidgetId.toString()).apply()
      val launchIntent = context.packageManager.getLaunchIntentForPackage(...)
      launchIntent.putExtra("appWidgetId", appWidgetId)
      launchIntent.flags = FLAG_ACTIVITY_NEW_TASK or FLAG_ACTIVITY_CLEAR_TOP
      val pendingIntent = PendingIntent.getActivity(context, appWidgetId, launchIntent, ...)
      views.setOnClickPendingIntent(R.id.widget_text, pendingIntent)
  } else {
      // Configured → cycle to next item (internal broadcast)
      val tapIntent = Intent(..., "com.quotewidget.WIDGET_TAP", widget_id=appWidgetId)
      val pendingIntent = PendingIntent.getBroadcast(context, appWidgetId, tapIntent, ...)
      views.setOnClickPendingIntent(R.id.widget_text, pendingIntent)
  }

Flutter deep link flow:
  1. Kotlin writes tapped_widget_id to SharedPreferences → opens app
  2. main.dart reads tapped_widget_id → passes to QuoteWidgetApp
  3. QuoteWidgetApp checks: if tappedWidgetId != null → shows WidgetSetupScreen
  4. WidgetSetupScreen: user picks collection → creates WidgetConfig
     → registers mapping → syncs data → widget updates

New file: lib/screens/widget_setup_screen.dart
  - Collection picker for first-time widget setup
  - Shows all collections with item counts
  - Creates WidgetConfig + registers appWidgetId↔configId mapping
  - Syncs data via HomeWidget.saveWidgetData()
  - Triggers HomeWidget.updateWidget() to refresh
